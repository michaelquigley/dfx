# 2026-10-06 — NodeCanvas per-declaration colors

Asked for by patchbay's placement loop (media hues on blocks and links). `NodeFlags.Accent` and `LinkFlags.Color` use zero-means-unset `imgui.Vec4` rather than pointers. That keeps both flag structs plain comparable values like the rest of the declaration API, and a fully transparent black accent has no use. Don't switch to `*imgui.Vec4` for "explicitness"; it would make every flags literal allocation-prone and uncomparable.

Selection is a thicker line in the element's own color, highlighted (lifted 30% toward white, opaque): the selected border of an accented node, the selected stroke of a colored link. Michael's call after seeing the first version: the style's red selection color clashed with blue accents, and the thickened line is the real selection indicator. The first version kept the style's selection color, so selection read the same on every node, and that was reversed deliberately; don't restore it. The title band keeps the accent when selected. Hover still uses the style's colors, and elements with no declared color keep the style's selection color. The precedence lives in the pure `titleBandColor`, `pinColor`, and `linkColor` in `nodeCanvasStyle.go`, which `nodeCanvasStyle_test.go` covers headless.
