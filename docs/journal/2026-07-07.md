## Gotchas the documents encode (verified against pinned cimgui-go v1.5.0 source)

- `imgui.FontSize()` must never be passed to `PushFont` — use `imgui.CurrentStyle().FontSizeBase()`.
- The canvas-level drawlist split must use an owned `imgui.DrawListSplitter`, never `ChannelsSplit` (imgui tables split internally; the convenience path can't nest).
- `fmt.Sprint` of a struct pointer renders `&{fields}`, not an address — the ID scoping rule special-cases pointer kinds via `%p`.
- Material icon merge uses fixed pixel glyph offsets (`fonts.go:48,75`) — icon baselines at reduced detents are a watch item for stage 3.

### Post-closure fix: delete-node segfault (example bug)

Michael hit a segfault deleting a node: `nodes["gain"].pos` nil-deref in the draw closure after `deleteSelectionCommand` removed `gain` from the map. Root cause was the example declaring nodes via hardcoded per-node `nc.Node("gain", nodes["gain"]...)` calls — fine until the model shrinks. The canvas itself was never at fault (it rebuilds geometry from declarations each frame and skips links to undeclared pins).

Fix restructured the example to the correct immediate-mode pattern — the one baab should copy: each `node` carries a `content func(*NodeContext)` closure, and the draw loop iterates the *currently-existing* nodes in sorted-ID order (`for id := range nodes`), so a deleted node is simply absent. No hardcoded `nodes["x"]` in the draw path remains. Also hardened `moveNodesCommand.Run/Undo` to skip a vanished node (covers the delete-mid-drag race, where a still-in-flight `dragNodes` gesture emits `NodesMoved` for a node deleted that same frame).

Verified at runtime, not just by reasoning: a scratchpad harness (`OnTick`-driven, no interactive input) deleted `gain` (cascading its 3 links) then `source` across frames and rendered the shrunk graph clean to exit — the exact path that crashed. `make test` green; terminus re-review clean.
