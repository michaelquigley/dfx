# 2026-10-20

## Complete styles stage 3: Faceplate default

Nil `Config.Style` now resolves to Faceplate (`setupFontsAndTheme`). The fallbacks used outside a running App deliberately stay Classic: `CurrentStyle()` and the `currentStyle*` helpers. An application that drives its own ImGui context without `App.Run` sets it up through `SetupFonts`, `DefaultStyle` and `ModernDark`, which still mean Classic, so the component defaults must match them. Do not flip the fallbacks with the default.

Test traps:
- **Shared contexts.** ImGui's `CreateContext` keeps an existing context current. Several `styleTestContext` calls in one test therefore run in the first context, and hue schemes then inherit the previous theme's slots. `startupPresentation` gives each startup its own subtest for this reason.
- **Cascading failures.** A `t.Fatal` inside `OnSetup` aborts the run and makes later fader tests fail too. Read the first failure, not the last.

Examples were checked without screenshots: GNOME on Wayland would prompt for screen capture. The method was a scratch `-overlay` of `app.go` and an added audit file that lists windows with `imgui.CurrentContext().Windows()` after the root draws, then diffs Faceplate against Classic. That vector's `Data` wraps ImGui's C pointer array, so `Slice()` returns garbage: read the array directly. The named examples (composition, mixer, logviewer, nodecanvas) showed nothing new.

The fixes went where content clipped under Faceplate's spacing. Windows were enlarged in controls, lifecycle and hcollapse; workspace and hcollapse now use the measured remainder instead of a fixed subtraction; vumeter widens its panels by `Chrome.ContentPadding` in `OnSetup`; config's first-launch sizes grew.

Known clipping left alone:
- **HCollapse titles.** A title is shown once a panel exceeds `MinWidth+50`, not when the title fits. Widening vumeter's Waterfall (2ch) panel exposed this. Changing the rule would also change Classic.
- **Unchanged under both styles.** The fixed 300 px controls panel in nodecanvas_stress, the simple example's long line, and vumeter's Waterfall (8ch) header clip in Classic too.

Terminus review `f63d68b3fe11` was `clean`. Its advisory F1, retire the realized spec/work-order pair, waited for final acceptance (now complete; see closeout below). F2 re-raises the vetoed layout-guide Mermaid finding.

## Stage 3 audition: child windows, hcollapse, layout

Michael's audition found plain `BeginChild` regions under Faceplate looking like panels with no margins. The cause: `FaceplateTheme` painted `ColChildBg` at full alpha, but ImGui gives a child no padding unless it draws a border or asks for padding, and `ChildBorderSize` is 0 in both styles. Michael chose to make the slot the panel hue at zero alpha, as Modern Dark does. He rejected two alternatives: a child border size of 1, which leaves borderless children flush, and fixing only the examples, which leaves every application's children flush.

Dash and HCollapse keep the panel surface only because `SetNextWindowBgAlpha` overrides the slot's alpha. Remove that call and those panels go unpainted. The `Panel` role still binds to `ColChildBg`, so it now reads a transparent color. That is deliberate and documented; nothing in dfx reads the role. Child backgrounds are drawn into the parent's draw list when the parent ends, which is why `TestFaceplate_PlainChildrenUnpaintedPanelsPainted` inspects the host's list after `End`.

Example fixes:
- **hcollapse mixer panels:** sized in `OnSetup` by `mixerPanelWidth`, which reproduces Classic's 300 px exactly. The window is now 1300 wide. The main area's text wraps, using `Bullet()` plus `Text`, because `BulletText` ignores the wrap position.
- **layout demos:** moved into a scrolling `##demos` child, because the root window does not scroll.
- **composition, workspace, mixer:** each called `EndChild` only inside `if BeginChild`. ImGui requires `EndChild` after every `BeginChild`, so those calls now sit outside the conditional.
