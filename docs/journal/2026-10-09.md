# 2026-10-09 — app id

- `Config.AppID` reaches glfw's `glfwWindowHintString` through dfx's own cgo (`appId.go`), the package's first. cimgui-go exposes only integer window hints, and the string hints are the only way to set the Wayland app id and X11 class. No header is included: glfw is statically linked by cimgui-go's glfw backend, so the extern resolves at link time, and the hint constants are copied from glfw 3.4's header. If cimgui-go ever links a shared glfw or exposes string hints, revisit.
- Ordering is load-bearing: glfw must be initialized (the backend's construction does it) and the hint must precede `CreateWindow`. The hint is a package var, like `createBackend`, so the headless tests can observe the order without a display.
- Driven by patchbay's desktop integration (its `docs/journal/2026-10-09.md`). Adoption there waits for Michael's tag and a dependency bump.

## Fader appearance

- The custom fader paint keeps `VSliderFloatV` as its input and navigation item. Paint and scale share the same 2-pixel padding and half-grab-height inset as `SliderBehavior` in cimgui-go v1.6.0; check that formula when upgrading the dependency. The temporary `GrabMinSize` override must match the painted handle height.
- The reference bank uses linear taper because its values are already dB. It deliberately omits the screenshot's stereo meters and channel controls; this session changes the fader, with the wider channel-strip composition left separate.
- Michael accepted the prototype's shape, then asked for its colors to come from the theme. The fill uses `ColButtonHovered` deliberately rather than `ColSliderGrab`: Modern Dark's yellow lives in the former, while its slider grab is white. Keep theme lookup in drawing so creating parameters needs no ImGui context and changing a theme works immediately.
