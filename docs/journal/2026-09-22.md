# 2026-09-22 — NodeCanvas overlap and stacking

Michael reproduced simultaneous cutoff/level wheel edits with gain covering filter. Synchronous `Node` callbacks are a deliberate requirement: deferring callbacks to `End` for reverse-order input processing was proposed and declined because synchronous execution is part of the immediate-mode programming model. The agreed direction uses retained geometry for widget input and app-owned declaration order for raising nodes. Later declarations cannot retroactively undo an earlier callback's mutation; the last completed frame is the routing reference, with that boundary documented explicitly.

After committing the overlap work, Michael approved the next concern: cancel a pan on lost input and preserve its last valid view, while allowing a normal release outside the canvas. The unavailable-position sentinel could also overflow at reduced zoom and stall grid drawing, so guarding only `End` would be too late: the shared validity check must protect `Begin`'s preview too.

After the input-loss fix, Michael approved canceling a pending fit on pan initiation, before any movement. This must be independent of `viewChanged`: `Begin` has already applied the preview pan to the view that `stepPan` compares against. The existing behavior for wheel attempts clamped at a detent limit remains unchanged.
