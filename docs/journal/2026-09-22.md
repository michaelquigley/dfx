Synchronous `Node` callbacks are a deliberate requirement: deferring callbacks to `End` for reverse-order input processing was proposed and declined because synchronous execution is part of the immediate-mode programming model. The agreed direction uses retained geometry for widget input and app-owned declaration order for raising nodes. Later declarations cannot retroactively undo an earlier callback's mutation; the last completed frame is the routing reference, with that boundary documented explicitly.

The other review concerns remain separate, for one-at-a-time discussion: focus loss can persist an invalid pan; panning fails to cancel a pending fit because `Begin` already transformed the view used in `stepPan`'s comparison; the owned C++ draw-list splitter has no production cleanup lifecycle.
