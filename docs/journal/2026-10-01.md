# 2026-10-01 — NodeCanvas zoom moves to ctrl+wheel

Michael asked for ctrl+wheel zoom because the wheel gets nudged while the middle button is held for a pan, and the stray zoom on top of the pan was the thing he wanted gone. Plain wheel is left unassigned on purpose; wheel-pans-vertically (with shift for horizontal) was proposed as the conventional pairing and declined for now, so don't add it as a "completion" of this change. The modifier is hard-coded, not a config knob, until something needs otherwise.

The gate lives in `sampleInput`, not the gesture state machine: the pure input tests still drive `inputSnapshot.wheel` directly and never see the modifier. The wheel accumulator resets whenever ctrl is up for the same reason it resets off-hover: travel banked without the modifier must not finish a step the moment ctrl goes down.

## zoom overlay

The overlay draws in `End` after the scaled font pops, deliberately: it is viewport chrome and must read at UI size at every detent, so it cannot share the declaration window's font push. It is drawlist-only on purpose (no `Dummy`, no item) for the same reason `Label` is: an item in the corner would register as hovered and the widget-first gate would then swallow ctrl+wheel and left presses over it. The on-by-default boolean is spelled `HideZoomOverlay` so the zero config keeps the overlay; don't flip it to `ShowZoomOverlay` for naming taste, that would silently turn it off for every existing caller.
